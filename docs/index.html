PiauíBench

Benchmark de 10 questões de múltipla escolha (5 alternativas) sobre geografia, história e demografia do Estado do Piauí, usado para comparar a acurácia de três LLMs pequenos executados localmente via Ollama.

Resumo

Acertos consolidados e custo de inferência por resposta.

Robustez: ordem fixa × alternativas permutadas

As mesmas 10 questões, com as alternativas embaralhadas a cada repetição. Um modelo que sabe a resposta mantém a acurácia; um que apenas prefere certas letras cai em direção ao acaso (20%). A queda mede viés de seleção posicional.

Barra sólida: ordem fixa Barra hachurada: alternativas permutadas

Distribuição das letras escolhidas

Quantas vezes cada modelo escolheu cada letra (execução com permutação). Um modelo sem viés distribuiria as escolhas de forma aproximadamente uniforme.

Acerto por questão

✓ = acertou (maioria das repetições) · ✗ = errou. A letra mostrada é a resposta mais frequente do modelo.

Rodar o benchmark no seu Ollama

A página chama a API local do Ollama direto do navegador. Nada sai da sua máquina.

Pré-requisito (CORS). Servindo esta página de localhost, o Ollama já aceita a conexão por padrão. Abrindo pelo GitHub Pages, é preciso autorizar a origem: 
OLLAMA_ORIGINS="https://gutoportelaa.github.io" ollama serve
No Linux com systemd: systemctl edit ollama, adicione Environment="OLLAMA_ORIGINS=https://gutoportelaa.github.io" e reinicie o serviço. Depois clique em Conectar.

Chrome, Edge e Firefox tratam localhost como origem confiável e permitem a chamada mesmo a partir de uma página HTTPS. No Safari, sirva a página localmente (python3 -m http.server -d docs 8000) em vez de usar o GitHub Pages.

Como incorporar ao benchmark oficial

O GitHub Pages serve arquivos estáticos e não pode gravar de volta no repositório — a persistência definitiva é via commit.

  1. Crie as questões aqui e clique em Baixar benchmark.json completo.
  2. Substitua docs/benchmark.json no repositório pelo arquivo baixado.
  3. Rode python3 bench/run_bench.py --runs 3 para regerar os resultados com o conjunto novo.
  4. Abra um Pull Request. O fonte de cada questão é o que permite revisar o gabarito.

Regra de qualidade: as cinco alternativas devem ser plausíveis e do mesmo tipo (todas municípios, todos anos, todos rios). Distratores absurdos inflam a acurácia e escondem o que o modelo realmente sabe.

Metodologia

Como a acurácia é medida.

  • Tarefa: QA de múltipla escolha (MCQA) fechada, sem contexto recuperado — mede conhecimento paramétrico regional em pt-BR.
  • Prompt: um system prompt fixo em português + a questão com as cinco alternativas rotuladas A–E, pedindo apenas a letra.
  • Decodificação: temperature = 0, top_p = 1, seed fixa e think: false (desliga o modo de raciocínio do Qwen3), garantindo reprodutibilidade.
  • Saída estruturada: usa o parâmetro format do Ollama com um schema JSON cujo enum é ["A","B","C","D","E"]. Isso elimina falhas de parsing e separa erro de conhecimento de erro de formatação.
  • Repetições: cada questão é feita n vezes (padrão 3) com sementes diferentes; a resposta considerada é a moda, e a acurácia global usa todas as chamadas.
  • Métrica: acurácia = acertos / total de chamadas. Baseline aleatório = 20% (1 em 5).
  • Limitação: com apenas 10 itens, o intervalo de confiança é largo (cada questão vale 10 p.p.). O resultado é indicativo, não conclusivo — veja "Como ampliar" no README.

Reproduzir localmente

git clone https://github.com/gutoportelaa/piaui-bench
cd piaui-bench

ollama pull llama3.2:3b
ollama pull qwen3:4b
ollama pull gemma3:4b

python3 bench/run_bench.py --runs 3
python3 -m http.server -d docs 8000   # abre http://localhost:8000
